# 分层、混搭与可追溯的设计工作台

用于完整 Logo / App icon 探索、元素混搭、配色与材质变体，以及原稿到 mock 的更新。目标是让设计师通过选择与组合已有资产推进设计，每次判断都能复用。局部修改直接进入相关阶段，不重跑研究、重建整套 Section 或补齐未请求的方案数量。

## 1. 六个角色在 Figma 中分别展示

完整探索要在实际项目文件里创建或复用下列独立 Section，逐步放入真实、可编辑、已检查的对比内容。仅在最终图标里分组，或在聊天里列出六层，不算建立工作台。

| 角色 / Section | 实际展示内容 | 比较时固定什么 |
| --- | --- | --- |
| `Background / 背景` | 容器轮廓、底板、独立背景风格 | 不加入主体；材质比较用同一轮廓 |
| `Shape / 主体形态` | 标志主体、气泡、键帽、字形等不同构形 | 统一配色、材质、展示尺寸 |
| `Expression / 表情` | 眼睛、嘴巴、眨眼及其组合 | 使用同一个承载形态、角度和尺度 |
| `Supporting Motif / 辅助图形` | 与产品有关的第二主体；键盘项目中展示底板、按键和空格键组合 | 统一主体和背景；独立比较辅助图形 |
| `Material / 材质` | 纯色、轻透、薄浮雕等有依据的处理 | 同一几何与配色，只改变材质参数 |
| `Presentation / 展示与 mock` | 选中方案的实际尺寸和目标使用场景 | 相同设备、壁纸、图标槽位置与尺寸 |

另外保留独立的 `Palette / 配色` Section 和 `Composition / 组合与最终方案` Section：前者展示色块及同形预览，后者组装已选元素、显示精细变体与最终候选。Reference 区继续按 `reference-board.md` 管理。已有 Background 和 Palette 区直接复用，不重复搭建。

这些是设计角色，不是每个品牌必须包含的图形。没有表情的字标不强加笑脸；没有第二主体的标志不强加键盘。完整项目先记录六个角色的适用性，对不适用角色记录 `not_applicable`，不建没有用途的空白 Section。项目中的“键盘”作为辅助图形的实例，不成为跨项目固定元素。

读取现有位置与邻近内容后在空白处建区，相关选项用 Auto Layout 排列。阶段按依赖推进，不要求六区同时完成。保留用户移动、删选和标注；不为整齐而重排历史工作。板面以图形为主，编号和名称放原生 section/frame/layer 标题，解释、色值记录和选择理由留在项目文件。

## 2. 层内可拆，层间有约束

组合保持可编辑角色，例如：

```text
Composition
  Background
  Foreground
    Supporting Motif
      Surface
      Details
    Shape
      Surface
      Expression
  Accent (optional)
```

实际前后顺序按构图确定；气泡需要浮在键盘前面时明确绑定层级。Material 是施加于角色的参数集合，Palette 是跨角色的颜色映射，两者不必伪装成单独的覆盖图层。

每个可替换资产记录锚点、适配框、承载对象和相关约束：

- 表情定位在主体局部坐标中，并随承载面缩放、倾斜；不直接把任意表情贴到另一个透视面。
- 阴影、底层、侧面和倒角关联主体轮廓。立体键帽的顶面、底面及分界由共同几何关系派生，不用加深或模糊掩盖结构错位。
- 混搭保留主体与辅助图形之间的遮挡关系、可见尖角及安全间距。检查光学居中，而不只看包围框中心。
- 改色不变形；改表情不改气泡；改材质不重新塑造轮廓。跨角色联动只修改完成当前意图所必需的部分。

## 3. 先发散，再受控展开

完整原创设计按 [workflow-1.0.md](workflow-1.0.md) 分阶段展开：

1. **6–12 个明显不同的初稿方向**，统一黑白/简单处理，并展示 2–3 个有代表性的分层组合。
2. **用户保留 2–3 个方向**；复用已有选择，普通偏好未回复按主流程记为暂选，不当作用户批准。
3. **每个入选意象约 25 个几何变体**，比较轮廓、比例、表情与中景，固定颜色材质。
4. **每个选中形体约 25 个色彩/材质变体**，另做背景比较；颜色已定时可缩减，不设置固定十组色板关卡。
5. **终选与混搭**：按评论建立终选方案1、2、3等新轮次；进一步广泛探索时每个候选约 25 款，局部修正则只改必要内容。选中结果进入 mock 并验收。

上述为完整项目的阶段目标，用户指定数量、局部编辑与已有选择优先；不是每轮都重新生成全部数量。不自动乘出所有资产组合。每轮继承上轮结论，锁定已满意的部分。

对比矩阵每次只改变一个变量：列可代表固定形态，行代表配色；换材质时固定配色与形态。需要同时探索两个变量时，让行、列各对应一个明确变量。形成新一轮时保留原版，把新增变体放在指定下方或相邻空白区；请求“更新/替换原版”时在原节点修改，不额外堆积重复区。

## 4. 分离配色与材质，显式锁定修改范围

配色按角色管理：背景、主体、表情、辅助底板、细节/按键、高光及阴影。参考中提取颜色关系，不直接把每一层都换成相近的蓝色。检查主体与背景、表情与主体、按键与底板三组分离度；白色也可作为保留角色。

材质单独记录 gradient type / transform / stop positions / stop alpha、paint opacity、layer opacity、blend mode、stroke 和 effects。渐变的颜色归配色；方向、色标布局和透明度归材质。角色颜色不能脱离小尺寸可读性单独判断。

每次修改在项目记录中写简短的 `changed_properties`、`locked_properties`、作用节点和输出方式。例如“键盘换成深灰、黑色、蓝色，保留渐变和透明度，在下面出方案”：

- 只修改键盘底板 fill 的 RGB；复制原稿新增对比。
- 保留渐变类型、变换、色标位置、每个色标 alpha、填充透明度、图层透明度、高光描边和阴影。
- 保留按键、表情、背景、位置、比例及尺寸。若要改按键色以实现新目标，应先判断用户当前是否允许，而不是悄悄修改锁定项。
- 完成后比较锁定属性；RGB 换色若产生截断或色阶损失，应调整映射并看实际渲染，不只检查赋值成功。

色板选择仍按 `palette-board.md` 执行。用户已授权一批配色试验或委托选择时直接开展，不为每种颜色追加确认。

## 5. 用稳定映射同步原稿、组合与 mock

复用项目的 `project.json` 或现有台账；没有时保存 `design-system.json`，按需记录：

- sections：角色、section_id、适用状态；
- assets：稳定 asset_id、角色、Figma node_id、SVG 母版路径/版本、锚点与约束；
- palettes / materials：稳定 ID、角色色值及材质参数，链接已有色板记录，不另存冲突副本；
- compositions：稳定 composition_id、原稿 node_id、使用的 asset/palette/material ID 与版本、variant_of、当前选择状态；
- edits：本次 changed / locked properties、验证结果；
- mock_links：composition_id、原稿 node_id、mock section/card/icon node_id、同步版本与状态。

名称和画布坐标可变，映射依赖 ID，不按相同名称或数组顺序猜测对应关系。写入前重读原稿与目标；用户手工修改优先。源节点删除或移动后重新确认其当前归属，不从旧 SVG 自动复活淘汰稿。

已授权的对应 mock 在原稿修订后同步更新，保持设备、壁纸、标签、槽位、尺寸和布局；新增探索不自动全量灌入 mock，按用户选中或请求的范围加入。“更新这个 Section”更新当前源集合的映射，范围外的既有对比默认保留；若用户要求完全替换，则据此协调移除和新增。当前无可用原稿的映射不伪装为已同步。

### 最终方案默认联动 mock

用户确认最终/入选方案，或明确指定某个方案区持续用于展示后，将该范围记为 `mock_sync_scope`。在已有目标 mock 或已获创建展示区授权时，为范围内的最终组合建立对应展示；之后每次由代理完成原稿修改，都在同一轮任务结束前更新对应 mock 并看小尺寸效果，不等用户再次说“更新进 mock”。这里的“最终”是当前入选状态，不表示设计以后不能继续改。

优先复用既有同步方式。新建、适合复用的最终资产可采用 Figma 主组件与 mock 中的实例，使主组件修改由 Figma 原生传播；创建组件前加载对应的 Figma component/library 指引。保持整体等比缩放，并检查实例覆盖是否阻止预期更新。不要为了联动强制转换用户正在自由编辑的原稿、解除已有实例或重建整批 mock。普通矢量原稿继续使用任务内同步。

任务内同步顺序：重读源与映射 → 更新受影响的图标槽（新增入选款才新增卡片）→ 检查尺寸、位置、内容和小尺寸呈现 → 记录 `source_revision`、`synced_revision` 与 `sync_status`（current / stale / blocked）。失败时保留可用的旧展示并报告未同步项；若旧图标已移除则先恢复备份。无变化时避免重复创建。更名或移动不改变映射；退出入选范围不自动删除历史比较。

普通矢量的同步由代理在任务内执行，不能声称会在代理未运行时监听用户手动编辑。只有实际建立并验证的 Figma 主组件/实例才能称为原生联动；连续后台监听需另行实现，不能靠 skill 文本获得。此规则不授权发布或向外部人员发送设计。

## 6. 验收与交付

检查真实 Figma 板面：各区有可用对比、数量与范围一致、没有重复堆叠或覆盖；大图检查几何/接头，小图和实际 mock 检查辨识度、比例与层间对比。核对锁定属性与源到 mock 映射，导出最终选中矢量母版。视觉检查、代理推荐、用户选中分别记录。

交付相关 Section 或最终候选链接及必要的简短说明，不把参数台账塞进画布。任何无法完成的 Figma 导入或 mock 同步如实记录为待完成。
